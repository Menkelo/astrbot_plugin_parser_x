# 0.9.0 媒体补全与验收

## 已实现的行为

| 场景 | 现在的行为 |
| --- | --- |
| B站视频动态、转发视频动态 | 从 archive 中取 BV/AV 编号，复用现有视频解析、清晰度限制和视频评论流程 |
| 微博独立视频 fid / 不带 mid 的 tv/show | 调用视频播放信息接口，发送视频 |
| 微博 App 分享 | 解析分享跳转后进入已支持的微博路由 |
| 小红书实况 | 读取图片条目的 stream，优先 H.264，作为短视频发送 |
| 抖音实况 | 支持 images、image_post_info、slides；读取图片条目的播放地址与 bit_rate 备选结构 |
| 微博实况和混合媒体 | 读取 pic_infos 与 mix_media_info，保留图片、实况及多视频顺序 |
| 单段不可用 | 实况有静态图时回退静态图；其他失败媒体不阻断后续项 |

纯实况使用 DynamicContent，不被视为需要抓取评论的普通视频作品。小红书评论仍完全移除。
多项媒体使用原生合并转发，失败后逐段发送；没有新增失败时附加标题、原链接的功能。

微博已有 Cookie 配置时优先请求网页作品接口，保留移动端可能省略的实况与混合媒体字段；
该接口不可用时继续尝试移动端和详情页。没有新增账号注册、扫码登录或第三方解析服务。

## 验证结果

环境：Windows、Python 3.12.14、AstrBot 4.28.2。

- `python -m pytest -q`：215 passed。
- 新增 `tests/test_media_completion.py` 的 31 项回归，涵盖四类微博视频入口、App 跳转、无效
  播放信息、视频动态/转发动态、实况主备地址、无封面片段、混合媒体顺序、单段失败、静态图
  回退、评论范围和请求上下文隔离。
- 缓存与其余平台的已有测试同时通过。
- Ruff 检查、全仓格式检查与语法编译通过。

### 真实网络检查

以下检查不使用账号 Cookie，不向 QQ 发送消息：

| 公开样本 | 结果 |
| --- | --- |
| `video.weibo.com/show?fid=1034:5145615399845897` | 实际新解析器输出一个视频、时长 4.9 秒；媒体 Range 请求为 206，读到 MP4 文件头 |
| `weibo.com/tv/show/1034:5007449447661594` | 实际新解析器输出一个视频、时长 246.3 秒；媒体 Range 请求为 206，读到 MP4 文件头 |
| B站动态 `1120105154190770281` | 匿名详情接口返回 -352，本环境无法据此完成在线验收 |
| 微博实况 `OuxSwgUrC`、混合媒体 `MxojLlLgQ` | 移动端/网页匿名请求返回非 JSON，未使用登录态绕过 |

因此只确认上述两个微博视频样本的在线解析与媒体可读性，不声称对其余平台测得了实时成功率。
实况、混合媒体及 B站动态分支已在实际插件函数与消息构造流程中使用结构样本完成回归；
小红书、抖音实况与真实 QQ 投递还需要部署环境中的实际作品验收。
