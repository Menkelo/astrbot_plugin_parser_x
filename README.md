# Parser X

面向 AstrBot 的国内平台作品链接解析插件。发送分享链接，即可获取视频、图片及统一样式的作品卡片与热门评论。

- **AstrBot 版本：`>=4.26.0,<5`**
- **消息适配器：仅支持 aiocqhttp / OneBot v11**，可在群聊和私聊使用。
- 卡片使用本地 Playwright Chromium 渲染，字体随插件提供，不需要外部截图服务。

## 支持平台

- **B站**：视频、分 P、动态及热门评论，视频动态可转入原视频解析。
- **抖音**：视频、图文、图集及热门评论。
- **快手**：视频、图片、混合媒体及视频热门评论。
- **微博**：文字、图片、视频、混合媒体及热门评论。
- **小红书**：视频、图文笔记及热门评论。
- **小黑盒**：帖子、正文、图片、可识别视频及热门评论。
- **AcFun**：视频及热门评论。

全部平台默认启用。作品与评论能否获取，取决于接口可用性、登录态、账号权限和平台风控；不保证每个作品都有评论卡片。直播、已识别的非作品页面，以及群内非常规卡片消息会静默跳过。

卡片支持作者/置顶标识、楼中楼、平台表情和评论配图。媒体按作品顺序发送，多个产物通常以合并转发交付；实况图不保证还原手机相册的原生 Live Photo。

## 安装

在 **AstrBot WebUI → 插件管理** 中使用仓库地址安装：

```text
https://github.com/Menkelo/astrbot_plugin_parser_x
```

运行环境还需准备：

- **ffmpeg**，且 AstrBot 进程能够从 `PATH` 找到它。
- 插件 Python 依赖，包括 **Playwright `>=1.58,<2`**。
- 与 Playwright 包版本匹配的 **Chromium** 及其系统库。安装 Python 包不等于安装浏览器，插件不会自动安装浏览器或系统软件。

在 **AstrBot 实际运行的容器、Python 环境和用户**下安装浏览器：

```bash
python -m playwright install chromium
```

**Docker 用户注意：** AstrBot 和 OneBot 协议端在不同容器时，通过本地路径发送的媒体必须能被协议端读取。通常需要将本插件数据目录共享到协议端的相同绝对路径；网络互通不等于文件互通。

依赖、系统库、目录挂载示例及环境验证步骤见 [安装指南](docs/INSTALL.md)。修改挂载前请先备份，避免重建容器丢失登录态或容器内安装的依赖。

## 使用与配置

直接发送支持平台的作品链接或含链接的分享文案即可。

管理员可在对应会话使用：

- `/开启解析`：开启当前会话解析。
- `/关闭解析`：关闭当前会话解析。

### 常用配置

- **热门评论 / 卡片开关**（`comments.enabled`）：默认开启。关闭后不生成或发送插件生成的卡片，也不复用旧卡片；原始媒体与原生正文不受影响。
- **评论数量**（`comments.display_count`）：默认 10 条，范围 1–20；首条可用楼中楼不占主评论数量。实际条数受平台返回和过滤结果影响。
- **视频源编码偏好**（`performance.video_codec`）：可选 `auto`、`hevc`、`avc`，默认 `hevc`。自动模式保留各平台原选择；明确偏好只从已提供且可识别编码的源中选择，没有目标编码就回退，**不强制转码**。只有单一源或 CDN 镜像的平台保持原源。
- **平台 Cookie**（`cookies.*`）：按需填写，见下节。
- **已关闭解析的会话**（`behavior.disabled_sessions`）：通常通过命令维护，记录的是完整会话标识，不是单独的群号。

单资源大小上限固定为 **100 MB**。评论过滤默认启用：保留正常正文中的 `@用户`，过滤纯提及、纯喊人评论，并进行广告、二维码配图和重复评论过滤；楼中楼也会单独过滤。

## Cookie 与账号风险

粘贴已登录网页请求中的完整 Cookie，例如 `key=value; key2=value2`，**不要包含 `Cookie:` 前缀、JSON 或文件路径**。建议使用专用小号，失效后手动更新。

- **B站**（`cookies.bili_ck`）：可选，用于作品、动态和评论请求，并影响可用清晰度；留空按匿名方式尝试。
- **抖音**（`cookies.douyin_ck`）：用于作品解析和热门评论；热门评论需有效 Cookie。
- **快手**（`cookies.kuaishou_cookie`）：可选，仅用于热门评论，留空按匿名方式尝试；填写后也不保证通过风控。
- **微博**（`cookies.weibo_cookie`）：公开作品可匿名尝试；热门评论需有效 Cookie。
- **小红书**（`cookies.xiaohongshu_cookie`）：用于作品解析和热门评论。填写后，统一评论开关开启时会对满足条件的作品尝试抓取评论，没有独立的平台评论开关。
- **小黑盒**（`cookies.xiaoheihe_cookie`）：用于帖子与热门评论；不填可能触发验证码或解析失败。
- **AcFun**（`cookies.acfun_cookie`）：可选，用于视频解析、下载和热门评论；留空按匿名方式尝试。

**小红书等平台可能触发账号验证、限制甚至封禁，没有“不封号”保证。** 不接受小红书账号风险时，请勿填写其 Cookie，或关闭统一评论开关（会影响所有平台的卡片与评论）。Cookie 不能绕过付费、地区、权限或验证码限制。

配置和缓存可能包含登录态及私人作品内容，部分下载流程还会生成 Cookie 文件。**不要公开分享配置、缓存或未经检查的诊断资料。**

## 调试台

从 AstrBot WebUI 插件详情打开 **解析调试台**，可查看解析结果、媒体和任务事件。

默认情况下，QQ 和调试台均可解析。开启 **“只响应调试页面”** 后，QQ 分享不再触发解析；关闭并等待插件重载完成后恢复。调试台使用当前插件的配置与登录态，不代表支持其他消息适配器。

## 常见问题

### 解析成功，但媒体发送失败？

先检查协议端能否读取实际媒体路径。Docker 部署优先检查共享目录、路径大小写及读取权限，详见 [目录共享说明](docs/INSTALL.md#docker-部署媒体目录共享)。此外，文件大小、格式兼容和协议端自身错误也可能导致发送失败。插件会尝试失败降级，仍失败时提示并附原链接。

### 为什么没有评论或卡片？

检查统一评论开关、对应平台 Cookie 和调试台结果。平台可能要求登录、返回较少评论或触发风控；过滤后也可能不足设置条数。评论失败不应阻断原始媒体。

### 为什么群里不解析，调试台却可以？

检查是否开启“只响应调试页面”，以及当前会话是否被 `/关闭解析`。直播、非作品页面和非常规卡片消息属于主动跳过，不是解析失败。

### 为什么重复解析仍显示之前的评论？

生成卡片会按作品输入、配置与渲染版本落盘复用，命中时不会重新抓取评论。成功解析结果另有短期内存缓存，并发相同请求会合并处理，但分别回复。缓存目录位于 AstrBot 数据目录的 `plugin_data/astrbot_plugin_parser_x/`；每天 00:00 按 AstrBot 时区（未配置时为 Asia/Shanghai）清理超过 24 小时未更新的缓存文件。

### 卡片渲染需要联网吗？

页面截图使用本地 Chromium 和随插件提供的字体，不依赖远程截图服务。作品、头像及平台自定义表情等素材仍可能需要下载，因此整个解析流程并非离线。
